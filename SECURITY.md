# Security Policy

## Reporting a Vulnerability

If you discover a security issue, report it privately to:

`amalsdev367@gmail.com`

Do not open a public issue for unpatched security problems.

## What to Include

Please include:

- affected component or endpoint
- impact summary
- reproduction steps or proof of concept
- any relevant logs or screenshots
- whether the issue is already being exploited, if known

## Response Expectations

Best-effort triage will usually follow this flow:

1. Acknowledge receipt
2. Validate and reproduce the issue
3. Prepare a fix or mitigation
4. Coordinate disclosure timing if the report is valid

## Scope

Security reports are especially useful for:

- authentication or authorization bypass
- token, cookie, or session handling issues
- file or artifact exposure bugs
- prompt or provider abuse paths
- SSRF, command execution, path traversal, or injection bugs
- secrets disclosure

## Supported Versions

Security fixes are prioritized for the current active branch and the current release line leading up to `0.1.0`.
